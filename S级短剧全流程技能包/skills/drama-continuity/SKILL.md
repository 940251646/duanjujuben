# 连续性与事实台账

读取 [项目协议](../s-drama-master/references/project-contract.md) 和 [核对程序](references/continuity-audit.md)。输入当前 canon、实际正文、改动范围与最近一次核对位置。涉及人物命名时读取 [命名设计规则](../drama-characters/references/name-design.md) 和 `canon/name-ledger.md`；涉及人物造型、场景和道具时读取 [资产版本规则](../drama-ai-production/references/asset-versions.md)，同时核对 `production/资产版本库.md`、`production/逐场资产绑定.md`、`production/资产变更记录.md`。

1. 提取已经发生的事实，与拟写计划区分。新增事实先标来源集场；姓名、别名、称谓也当作事实管理，不用相近姓名悄悄替换。
2. 用 [台账模板](assets/continuity-tables.md) 核对人物身份、能力、时间、知情范围、物件和承诺；有数值时逐笔演算。
3. 先核对姓名台账：每个出现在正文的 C 编号是否有锁定姓名或有依据的临时称呼；全名、昵称、化名与台词称呼是否映射同一 C 编号；同场是否出现同音、近音、字形近似或不符合时代/关系的称呼。改名场景必须有旧名→新名、来源集场、影响范围和全文回归结果，不能只改当前集。
4. 逐个核对已写场次的资产绑定，以故事时间追踪入场、动作和出场状态；呈现集序另记。换装、妆容、发型发饰、昼夜、时代、损坏修复和持有交接有承接依据；闪回绑定对应历史变体。同场发生状态变化时拆成动作段或镜头绑定。承担证物、赠礼或身份功能的发饰使用独立 P 编号，角色佩戴关系引用同一物件实例。
5. 发现矛盾给出两个冲突位置、受影响剧情和最小可行修订。采用用户意图与稳定 canon 作依据，避免临时新增万能规则补洞。缺失姓名绑定、称呼依据或资产绑定写入问题表，设计计划保持 `planned`，正文已落定的绑定标 `written`。
6. 修改先前规则、姓名或资产变体时搜索所有依赖场景；连同对白、分集、伏笔、制作资产同步检查。姓名改动应检索全名、昵称、拼音、字幕和心声；`C01-V01@r001` 的素材修订与人物换装属于不同变化；保留过去引用和变更来源，明确哪些场次需要重绑或重新制作。
7. 主控合并 canon_delta 后增加版本。多人写作时保持一名合并者，其他人只提交提案。
8. 多季续写先核对 [多季交接协议](../s-drama-master/references/multi-season.md)、上一季交接、系列 canon 和跨季账。姓名、关系结果、能力边界、知识、资源余额、伤病、妆发、发饰、场景损坏和道具持有人逐项继承；若因季间时间跳跃变化，给出变化发生时间与证据。跨季改稿沿全局图查所有受影响季和交接文件，不限于当前集。

输出更新后的 `canon/` 文件、上述三份资产产物的必要修订和 `review/issues.md`，附 evidence、canon_delta、open_issues、next_stage_inputs。资产字段维护在制作附件，文学正文保留自然的服装、空间和动作描述。没有发现矛盾也记录实际核对范围，保留未核对的部分。
