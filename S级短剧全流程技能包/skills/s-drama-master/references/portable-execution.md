# 跨 AI 执行与多季完整创作

## 手动季数启动块

每次启动可直接填写：

```text
计划季数：1/2/3/…（未填写按1季）
每季集数：120 或 120,100,120
当前创作季：S01
本季总时长硬上限：8400秒（140分钟）
前三集：120—180秒/集；后续集：60—90秒/集
```

目录宿主按季创建 `seasons/S01`、`seasons/S02`；聊天宿主在交接块中重复当前季和累计秒数。收到“继续 S02”时先读 S01 交接、系列 canon 和系列故事图，不重写 S01，也不把未提供的季间事实当成正典。

## 三种宿主环境

1. **可读取目录、可写文件、可多轮执行**：读取总控，按路由只加载当前小技能，逐批写入项目文件；保存 canon 和进度，自动进入下一批直至约定范围完成。
2. **支持附件与长上下文，主要通过聊天输出**：上传总入口与当前必要模块，正文分批输出；每批附完整交接块。接近输出上限时在完整集结束处停止，准确写出下一集。宿主支持续写则继续；否则下一条“继续”直接恢复，免去重新策划。
3. **只接受单段提示词**：使用单文件版，按章节定位对应技能。材料超过上下文时优先保留用户规格、当前 canon、全剧阶段表、邻接分集、待兑现承诺和当批规则，避免截断后假装记得全稿。

“调用小技能”指读取其工作流程并实际产生结果，不依赖平台存在函数调用 API。没有文件系统时用清楚的文件名标记输出块；未实际保存的文本不声称文件已创建。没有多轮自动运行能力的宿主使用交接块续写，完整性以当前季约定集数实际产出为准；多季需逐季确认。

## 多季与120集长篇的组织

用户当前默认规模为每季120集；题材按项目选择，正文保留对白、内心独白、心声、旁白和必要系统音。启动时读取 `season_count`：可以手动输入 1、2、3……，也可以只启动 S01 并在后续调用时指定季号。每季拥有独立的 `episode_count`、`episode_runtime_seconds` 和 `max_total_seconds: 8400`；系列累计时长可以超过140分钟。先核对当前季总秒数与每集范围、前三集规格是否同时成立。

- 单季项目先写本季终点与关键关系终点；多季项目先写系列终点，再为每一季写可收束的季终点和季间代价。把当前季分成能产生真实进展的阶段。可用6—10个阶段作为起点，阶段长度由事件变化决定。
- 每阶段至少说明进入条件、阶段目标、主要阻力、主角策略、阶段结果、实际代价、关系变化、引出的下一问题。
- 为当前季全部建立分集卡。允许设计稿逐批细化，但后段目标、高潮与本季结局先有可执行方向；多季的后续季可先建立季级卡和入口条件，未启动的季不伪造逐集正文。
- 给每个反复使用的机制记录“新场景、新策略、新后果”；仅改对手名字不算推进。连续同解法出现时设计对手适应、利益冲突或选择代价。
- 核心配角的个人目标贯穿阶段。每条支线说明如何影响主线结果；相同功能支线合并，避免为集数填充无后果事件。
- 每批默认3集，120集的一季可分40批执行。阶段边界做全局复核；每批做局部连续性和信息核对。跨季续写前先读上一季交接和系列图，续写后创建新的季间交接。
- 同批更新姓名台账（如有新角色或称呼）、资产版本库、逐场绑定与变更记录。下一批读取已锁定姓名、相关时期、服装妆发、场景和道具状态；关键发饰佩戴关系与独立道具实例保持对应。回忆所需历史版本一并带入。
- 最后一阶段先兑现本季核心承诺，再处理人物去向和余波；最后再留下有代价依据的系列线。下一季入口不得占用本季主矛盾的收束位置。

### 多季文件与启动顺序

`season_count` 只是计划数量。收到“继续 S02”时，读取 `series/series-canon.md`、`canon/season-handoffs/S01-to-S02.md`、`canon/cross-season-ledger.csv`、`series/series-story-graph.json` 和上一季最终审稿问题；创建 `seasons/S02/` 后再写本季定位增量与前三集。沿用全系列姓名、规则、人物本体和道具所有权，按故事时间选择资产变体，不复制 S01 的 `EP001`。

每季交付必须生成：

- `seasons/Sxx/04-runtime-budget.md`：本季逐集秒数与累计不超过8400秒的证据；
- `canon/season-handoffs/Sxx-to-Syy.md`：已兑现承诺、季末选择/代价、知识、资源、时间和资产状态；
- `series/season-index.md`：各季 `planned/drafted/reviewed/revised/delivered` 状态和文件入口；
- `series/series-story-graph.json` 的跨季边：上一季结果如何成为下一季条件。

季末既要解决本季主要承诺，也要交代余波；只留下“更大阴谋”而没有结果时标记 `open-cliffhanger-risk`。多季系列最终报告逐季列出完成范围，不能把只完成 S01 说成全系列完成。

## 进度字段

```json
{
  "project_name": "项目名",
  "mode": "full",
  "canon_version": 1,
  "season_count": 1,
  "active_season": "S01",
  "planned_episodes": 120,
  "season_status": "drafting",
  "stage": "drafting",
  "completed_episodes": [1, 2, 3],
  "reviewed_episodes": [1, 2, 3],
  "next_episode": 4,
  "current_arc": "阶段名",
  "last_scene": "EP003-S02",
  "open_critical_issues": [],
  "completion_status": "in_progress",
  "season_handoffs": [],
  "open_series_threads": []
}
```

completed列表只能加入实际存在的完整正文集，reviewed列表对应已读审稿集。计划完成和文本写完分别记。改稿影响旧集时移出对应reviewed状态，复核后恢复。

## 聊天交接块

```text
【续写交接】
项目／系列版本／题材／计划季数：
当前季／本季总集数／本季时长预算（每季上限8400秒）：
实际完整正文：Sxx-EP001—Sxx-EPxxx（若不连续，逐项列出）
已审稿范围：
当前阶段与最终目标：
上一集末状态：
人物位置、目标、关系、已知信息：
姓名台账版本；本批新增/改名/称呼及旧名传播范围：
当前故事时间/叙事层；下一批回忆对应的历史时间：
资产登记版次；相关C/L/P变体@r修订与进出状态：
妆容/发型/发饰佩戴关系；道具所有人、持有人和位置：
本批状态转换T编号；待复核素材修订与受影响集场：
本批新增规则与资源余额：
未兑现承诺：编号／首次出现／计划兑现集
下一集任务与前三个关键行动：
修改影响与待复核项：
下一步：从EPxxx开始写完整正文，沿用已定结局方向。
本季状态：进行中／完整且已审稿。
系列状态：仅当前季完成／等待续季／全系列完成。
季间交接：Sxx-to-Syy 文件路径、canon版本、跨季边和未回收系列线：
```

只恢复与当批有关的详细事实，同时保留可检索的全局索引。若旧稿缺失，明确缺口并请求所需最小材料；现有独立内容可继续整理。长上下文中周期性核对最初规格与结局，防止逐轮漂移。

## 完成审查

逐项核对当前季 `Sxx-EP001—Sxx-EP{N}`：是否有完整正文、是否有结束位置、是否完成连续性审查；检查三集开篇承诺、阶段升级、核心伏笔、高潮选择与结果。资产附件按正文场次核对覆盖，逐项保留变体定义、绑定、转换与历史修订；纯聊天输出时按文件名持续增补，交接块引用索引。多季再逐季核对交接文件和系列边。最终报告实际完成范围，区分文学稿、配音稿、资产文字设计、制作方案与已生成成片。
