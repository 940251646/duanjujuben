# 人物命名与原创性门禁

本规则解决一个常见问题：写作模型在未收到姓名时，直接从高频影视、网文或训练语料中取一个“顺手姓名”。**未由用户明确指定的姓名，必须重新设立、登记、检查后才可进入正文。** 本规则不承诺某个姓名在现实世界绝对唯一，而是通过项目约束、声音可辨识度和风险检查，尽量避免大众化、模板化和撞名。

## 1. 命名优先级与禁止默认值

1. 用户明确给出的姓名、别名或历史材料中的真实姓名属于项目事实：保留原写法，补齐读音、称呼和撞名检查；不要擅自“优化”成更特别的名字。
2. 用户未给姓名时，先执行本文件的命名流程，再写人物卡、分集大纲和正文。禁止把 `顾总`、`厉总`、`沈某`、`小美`、`阿强` 或模型刚想到的第一组男女主姓名直接当成正式姓名。
3. 暂未命名只能使用 `C01（男主，待命名）` 这类编号占位，并在 `name_status` 标为 `pending`；禁止让占位符或未经检查的临时名出现在可交付正文。
4. 改名不是润色。改名后建立旧名—新名映射，检索全部集、台词、心声、资产提示词、伏笔图和交付文件，保留改名原因及影响。
5. 项目续写先读 `canon/name-ledger.md`。已经锁定的姓名、别名和称呼不能因模型换轮次而重新随机生成。

## 2. 先建立“命名约束卡”

命名不是随意找两个好听字，而是从人物和世界中提取约束。核心人物至少填写：

| 约束维度 | 必填内容 | 例子（仅示意） |
|---|---|---|
| 故事时间与年龄 | 出生年代、当前年龄、是否跨时期 | 1990年代出生，三十多岁 |
| 地域与语言 | 家乡、迁徙史、方言/普通话、民族或家族命名习惯（如有） | 河口小城，外婆坚持用本地方言读音 |
| 社会位置 | 家庭阶层、职业、受教育程度、对外使用的正式程度 | 船厂工人家庭，工作场合用全名 |
| 关系与命名权 | 谁取名、谁有资格使用昵称、谁故意改称呼 | 父亲取名；只有姐姐叫乳名 |
| 声音轮廓 | 单/双名、声调走向、首韵母、停顿长度、是否适合被喊出 | 三字全名，第二字重读，急喊不绕口 |
| 角色功能 | 主线作用、秘密、身份反差、名字可承载的误会 | 名字与旧物线索有关，但不直接泄底 |
| 禁止联想 | 与现有角色、知名人物、热播网文或品牌过近的字形/读音 | 不与 C02 同声母同韵母 |

人物来源不明时，以当前故事需要的最小约束为准并标注假设，不能用“感觉像某类型”代替具体依据。

## 3. 生成候选名：有来源、有差异、有可读性

### 3.1 生成前的三枚种子

为每个核心人物选三枚不同维度的种子：

- **生活种子**：一件常用物、动作、地貌、家中叫法或职业词（例如旧船票、晒盐、修表）；
- **关系种子**：取名者、关系中的称呼禁区、人物想摆脱或守住的称呼；
- **弧线种子**：人物会作出的关键选择或要付出的代价（不把主题直译为姓名）。

种子只用来约束声韵和意象，不能直接拼成“物件＋美德”的直白标签。男主、女主和主要对手先生成至少 8 个候选，功能较小的配角至少 5 个，再逐一填入候选表；禁止只生成一个名字就自称完成。

### 3.2 男女主的差异化检查

男主和女主不要求刻意一冷一热或一文一武，但必须在至少三项上形成可听、可写的差别：姓氏、音节数、声调走向、社会来源、称呼层级、字形结构、角色意象。两人若同姓，必须有剧情关系依据；若是情侣或搭档，也不能只靠“一个字的同音变体”区分。

姓名要服务人物而非替人物贴性别标签：女主可以有锋利、朴素或中性姓名；男主可以有生活化或柔和姓名。是否“有看点”来自身份、关系和行动中的反差，不能靠生僻字堆砌。

### 3.3 可读性底线

- 正文读者和配音员首次看到能读出大致读音；生僻字、异读字、多音字必须在命名卡标注普通话读音与项目内固定读法。
- 避免同场角色共享相同声母＋韵母组合（如两名核心角色都读 `-chen`），也避免连续三个角色同一声调节奏。
- 视觉上避免只有一笔之差的字形，听觉上避免同音、近音和昵称互撞。
- 姓名不承担完整背景说明。背景、秘密和反转留给行动与道具；名字只提供可信的身份锚点或可回收的关系作用。

## 4. 风险筛查与评分

每个候选都记录证据，不能用“挺特别”作为唯一判断。建议 100 分制：

| 指标 | 分值 | 核对方法 |
|---|---:|---|
| 项目内独立性 | 20 | 与所有 C 编号的全名、姓、昵称、首字、读音逐项比对 |
| 口播辨识度 | 20 | 用角色名互喊、争执、远距离呼唤各试读一次，记录声母/韵母/声调冲突 |
| 时代地域可信度 | 20 | 与人物出生年代、家族和地区命名习惯对照，写出来源依据 |
| 角色与关系适配 | 15 | 名字、正式称呼、亲昵称呼是否支持身份差和关系变化 |
| 非模板化程度 | 15 | 搜索高频影视/网文组合、霸总或校园公式；多重高频信号需淘汰或重写 |
| 后续叙事价值 | 10 | 是否可自然产生称呼误会、身份确认或情感回收，而非强行谐音梗 |

70 分以下不锁定；70—84 分需写清风险和后续复核；85 分以上才可作为首选。分数是内部筛选工具，不是市场热度预测。

### 4.1 直接退回条件

- 与项目已有角色同名、同音或昵称几乎相同；
- 与现实中的公认公众人物、经典影视主角或当前项目参考作品核心人物形成一眼可识别的整组组合；
- 依赖“冷酷姓氏＋景深/司寒/北辰/墨寒”等多重网文模板信号，却没有时代、地域和人物来源证据；单个常见姓或字不自动退回，组合风险才是重点；
- 生僻到配音、字幕、读者无法稳定识读，且剧情没有必要；
- 名字本身提前说破谜底、阶层或反派身份，使行动没有悬念；
- 为了“独特”强行造字、堆砌生僻字、使用无法在输入法稳定输出的符号。

## 5. 锁定、称呼和改名传播

正式姓名锁定后，在 `canon/name-ledger.md` 登记以下字段：`C编号`、全名、拼音与固定读法、性别/身份（如剧情需要）、出生与命名背景、正式称呼、亲昵称呼、敌对称呼、禁用称呼、别名/化名、首次出现集场、姓名揭示方式、候选与淘汰理由、风险复核日期、版本和改名影响范围。

称呼是关系动作，不是台词装饰：

1. 首次见面用什么称呼要有社会依据；
2. 关系变近、决裂或伪装时，称呼变化要落在具体场景和动作上；
3. 心声、旁白、系统音沿用同一身份映射，不因叙述层切换而换名；
4. 只有项目设定允许读心、身份伪装或多重身份时，才让观众看到不同知情层的姓名；
5. 资产库、字幕、镜头表和声音提示统一引用 `C编号`，姓名变动由台账传播，避免历史场次被静默改写。

## 6. 开篇的姓名使用

开头可以先抛事件、误会、能力或反常动作，不需要第一句介绍全名。姓名在观众需要分辨行动者时自然出现即可。若使用“误会式”开头，先确认台词实际指向的物件或动作，避免靠角色硬解释；误会解除后的姓名、称呼变化应成为关系推进，而不是单纯笑话。

## 7. 示例（只演示流程，不是默认姓名）

项目种子：沿江旧货市场、女主修复收音机、男主代收一批来历不明的磁带；两人首次见面互以职业称呼。候选表经过读音和模板筛查后，可能留下两组**仅供该项目演示**的名字：

- 男主「阮泊声」（`ruǎn bó shēng`）：来自“停泊”和录音的“声”，但不直接揭示秘密；可被叫“泊声”或“阮师傅”，正式/亲近层级不同。
- 女主「桑见微」（`sāng jiàn wēi`）：来自旧磁带上忽强忽弱的细节观察，不把“修复者”写进名字；可被叫“桑姐”“见微”，称呼变化能体现关系。

这两个名字不是总控默认名，也不能复制到下一项目；新项目须根据自身时间、地域、人物经历重新走三枚种子、候选表和风险筛查。若项目用户已经给出姓名，示例全部失效，以用户姓名为准。
